# 30 分钟首轮扫描清单

## 0–5 分钟：选操作

- [ ] 选一个用户可感、有明确起止的操作；可以是请求、任务、构建或启动。
- [ ] 不知道选哪个时，先用现成监控的平均耗时 × QPS 排 Top-N；p99 另看体验。
- [ ] 写清起点/终点、形态（首次/重复、冷/热、单请求/并发）。
- [ ] 写下当前值与目标值（不知道就写"待测"，并写清目标值从哪来）。

## 5–15 分钟：画路径

- [ ] 拆 5–9 段，标出同步/异步、跨进程/跨网络、读/写、加锁区间。
- [ ] 每段填：时间（实测或估）、工作量（次数 × 单次成本）。
- [ ] 找最大的一段，再拆一层。

## 15–25 分钟：五问 + 扫浪费

对每段问：

- [ ] 必须做吗？
- [ ] 必须现在做吗？
- [ ] 必须做这么多次吗？
- [ ] 必须做这么重吗？
- [ ] 必须在这里做吗？

对照 12 类浪费，写出 5–10 个候选（下面是检查项，不是候选本身；写不下就跳过）：

- [ ] 重复
- [ ] 不必要
- [ ] 等待
- [ ] 搬运
- [ ] 分配
- [ ] 放大
- [ ] 重算
- [ ] 粒度
- [ ] 局部性
- [ ] 串行/争用
- [ ] 算法/结构
- [ ] 配置/构建

## 25–30 分钟：排序

- [ ] 用 `工作量 × 可消除比例 × 频次 × 单次成本` 估每个候选的上界。
- [ ] 标置信度（E0/E1，按 06 的表）。
- [ ] 标代价（人日）与能否回滚。
- [ ] 按 `上界 × 置信度 ÷ 代价` 排序，选 1 个做最小确认（计数或一次差分）。

## 产出

- [ ] 一张路径图
- [ ] 一份工作账本
- [ ] 一张候选清单（≥10 条，排序后取前 3）
- [ ] 一个待确认的候选与确认方式
