# 十二类浪费

沿热路径逐条对照。先查高频、跨网络、跨进程、落盘的部分，不要一次全查。

---

## 1. 重复

**定义**：同一份计算、查询、校验、解析在一条路径或多层各做一次。
**怎么找**：同一函数/查询在同一请求里多次出现（中间件、重试、装饰器）；循环里取不变值；上层校验过、下层再完整校验；缓存命中仍回源确认。
**不是问题**：重复是为了隔离故障域、安全边界或一致性。
**修法**：上提、记忆化、把结果作为参数传递、合并校验、明确只在一层做。

## 2. 不必要

**定义**：做了但结果没人用，或效果为零。
**怎么找**：赋值后立即被覆盖；全量重置、全零写入、no-op 调用；只为日志构造大对象而生产日志关闭；永远为真的条件；取 100 个字段只用 3 个。
**不是问题**：为了兼容旧接口、观测或安全兜底。
**修法**：删、惰性求值、按需取字段、把调试逻辑移出热路径。

## 3. 等待

**定义**：本可并行、本可通知、本可不等的操作被串行或阻塞。
**怎么找**：固定 sleep/轮询/超时；串行调用互不依赖的服务；锁内做 IO/RPC/日志；慢依赖阻塞整个响应；重试退避过长。
**不是问题**：等待是为了让状态稳定（例如等资源真正释放）。
**修法**：并行化、事件化、异步化、缩小锁范围、把等待对象改成通知。

## 4. 搬运

**定义**：数据在层间、进程间、网络间来回拷贝或转换。
**怎么找**：深拷贝、序列化再反序列化、编码再解码；大 buffer 拼接、字符串反复 `+`、流式数据先攒整块；跨进程传大对象；同一份数据在多层各转换一次。
**不是问题**：拷贝是为了隔离可变性、跨边界安全或协议要求。
**修法**：零拷贝、共享只读视图、按需投影、减少跨边界次数、批量传输。

## 5. 分配

**定义**：高频创建临时对象，造成分配器压力、GC 或内存带宽消耗。
**怎么找**：每请求 new 大对象/大集合/大字符串；循环内创建临时对象、装箱、闭包、正则；缓冲区每次重分配；缓存无上限或键本身是大对象。
**不是问题**：对象很小、生命周期短、分配器便宜，或复用会引入并发问题。
**修法**：对象池、复用缓冲区、预分配、减少装箱、把分配移出热循环。

## 6. 放大

**定义**：一次用户操作被拆成 N 次内部操作。
**怎么找**：N+1 查询；逐条 RPC/写库/发消息；逐页扫描、逐条校验/日志；重试放大；监控采样率过高。
**不是问题**：逐条处理是为了隔离失败、保证顺序或满足限流。
**修法**：批量查询/写入、合并 RPC、分页/游标、限制重试放大。

## 7. 重算

**定义**：结果不变或变化很慢，却每次重新计算。
**怎么找**：每请求解析同一配置/规则；重算派生值（权限、费率、路由表、索引）；重建连接/线程池/正则/序列化器；缓存从不命中（键错、TTL 太短、频繁清空）。
**不是问题**：数据变化快、缓存一致性成本高于重算、计算本身很便宜。
**修法**：缓存、预计算、启动时构建、增量更新、修正键与失效策略。

## 8. 粒度

**定义**：批次太小、锁太大、页太小、请求太碎。
**怎么找**：一次只写 1 条/读 1 页/发 1 条消息；整表锁/全局锁保护很小临界区；小包网络、小 IO、频繁 fsync；线程池任务太碎。
**不是问题**：小粒度是为了低延迟、公平性或故障隔离。
**修法**：批量、合并、分片、缩小锁范围、调整页/批大小。

## 9. 局部性

**定义**：访问模式与硬件/存储的连续性不匹配。
**怎么找**：随机读代替顺序读；指针追逐、对象分散、冷热数据混放；跨 NUMA；伪共享；缓存命中率低或被大扫描冲掉。
**不是问题**：数据本身随机，或重排成本高于收益。
**修法**：改变布局（数组代替链表、冷热分离）、预取、绑核/绑节点、分片。

## 10. 串行/争用

**定义**：本可并行的部分被共享资源串行化。
**怎么找**：全局计数器/锁、单例、单写者、单队列；池过小或队列无界；头阻塞；锁内做 IO/序列化/日志；大量线程抢同一把锁。
**不是问题**：串行是为了强一致、顺序或简化。
**修法**：分片、无锁结构、缩小临界区、读写分离、独立队列、调整池大小。

## 11. 算法/结构

**定义**：复杂度或结构与访问模式不匹配。
**怎么找**：循环里线性查找/排序/重建索引；用列表做成员判断、字符串拼键、哈希冲突；全量排序只为 Top-K、全量扫描只为几行；递归无剪枝、重复子问题无记忆化。
**不是问题**：数据规模很小，复杂度差异不影响耗时。
**修法**：换结构（哈希/树/堆/布隆）、增量算法、Top-K、索引、剪枝、记忆化。

## 12. 配置/构建

**定义**：默认设置、构建方式或部署形态造成的系统性浪费。
**怎么找**：生产仍开 debug/低级别日志/全量追踪；构建未优化、带调试符号、产物含无关文件；依赖重复下载、无缓存、全量重编；连接/线程/副本数与容量不匹配；启动加载未用资源；超时/重试/批量大小仍是默认值。
**不是问题**：默认值是为了可移植性、可调试性或安全。
**修法**：分环境配置、构建缓存、增量构建、按需加载、容量匹配。

---

## 快速对照

| 看到… | 先查 |
|---|---|
| 同一请求里同一查询多次出现 | 重复 |
| 写了没人读的字段/对象 | 不必要 |
| 串行调用多个独立服务 | 等待 |
| 大对象跨层传递 | 搬运 |
| 每请求大量临时对象 | 分配 |
| 列表慢、DB 调用次数随行数增长 | 放大 |
| 每请求解析同一配置 | 重算 |
| 一次只处理一条 | 粒度 |
| 随机 IO、缓存命中低 | 局部性 |
| CPU 高但吞吐不涨、锁等待高 | 串行/争用 |
| 数据量一大就慢 | 算法/结构 |
| 本地快、生产慢 | 配置/构建 |
