# 分层扫描清单

沿被测路径逐层问。先查与用户可感操作直接相关、且高频的层，不要一次全查。

---

## 1. 应用逻辑

- 热路径上有没有日志、序列化、反射、正则、异常构造？
- 同一计算/校验/解析是否在多个中间件重复？
- 是否为日志/监控构造大对象，而生产日志级别关闭？
- 循环里是否重复取不变值（配置、权限、长度）？
- 业务规则能否增量计算，而不是每次全量重算？

## 2. 数据访问

- 有没有 N+1（列表 1 次 + 每行 1 次）？
- 是否取全部列只用少数？有没有全表扫描、缺索引、索引失效？
- 事务是否过长，锁住不必要的行/表？
- 连接池是否过小，或连接被长时间占用？
- 是否重复查询同一份数据（同请求、多层之间）？
- 批量写入是否逐条提交？提交频率是否过高/过低？

## 3. RPC / 网络

- 有没有逐条调用可以合并的接口？
- payload 是否过大（整对象、整页、整文件）？
- 连接是否复用？有没有每请求重新建连/TLS 握手？
- 超时与重试是否放大下游压力？
- 有没有头阻塞（慢调用占住连接/线程）？
- 是否跨地域/跨可用区调用，而本可本地完成？

## 4. 并发

- 锁保护范围多大？锁内有没有 IO、RPC、日志、序列化？
- 有没有全局锁、单例、单写者、单队列？
- 池/队列容量与负载匹配吗？队列是否有界？
- 有没有大量线程抢同一把锁，CPU 花在自旋/切换？
- 异步任务是否真的异步，还是被同步等待？
- 失败重试是否在并发下被放大？

## 5. 内存

- 每请求分配多少对象/字节？有没有大对象、临时集合、字符串拼接？
- 有没有深拷贝、重复序列化、装箱？
- GC 频率与停顿是否与请求量相关？
- 缓存是否有上限、过期策略、命中率？
- 有没有泄漏：连接、句柄、监听器、线程、缓存键？
- 大对象是否跨层传递，而只需要少数几个字段？

## 6. 存储 / IO

- 访问是随机还是顺序？块大小是否匹配？
- 小写是否合并？是否每条记录一次 fsync？
- 有没有读放大（读 1 行取整页）、写放大（一次更新写多份）？
- 页缓存是否命中？有没有被大扫描冲掉？
- 文件是否被重复打开/关闭？压缩/解压是否在热路径？
- 临时文件/日志是否与数据盘争抢？

## 7. OS / 运行时

- 有没有系统调用风暴（大量小 read/write/stat）？
- 缺页/页错误是否异常？
- 调度是否抖动：run queue、上下文切换、CPU 迁移？
- cgroup/资源限制是否成为隐形上限（CPU 配额、内存上限、IO 限速）？
- NUMA：线程与内存是否跨节点？
- 中断/软中断是否集中在少数核？频率是否被降频？

## 8. 构建 / 启动

- 依赖是否重复下载？缓存是否命中？
- 是否全量编译/全量测试，而可以增量/只跑受影响？
- 构建是否并行？关键路径是否被串行步骤卡住？
- 产物是否包含无关文件？
- 启动时是否加载未使用的模块/配置/资源？
- 初始化是否串行？能否并行或延后？

## 9. 配置 / 部署

- 生产是否仍用开发默认值（日志级别、采样率、超时、批量大小）？
- 连接/线程/副本数与容量匹配吗？
- 缓存大小/过期时间是否合理？
- 限流/熔断阈值是否过低，导致重试放大？
- 部署形态是否引入额外跳数（网关、代理、附加代理）？
- 监控/追踪/日志的采样率是否本身成为负载？

---

## 使用顺序

```text
应用逻辑 + 数据访问   ← 大多数业务系统的主要浪费
RPC / 网络            ← 跨进程放大与等待
并发 + 内存           ← CPU 高但吞吐不涨、延迟抖动
存储 / IO + OS        ← 数据量/落盘相关
构建 / 启动 + 配置    ← 开发效率与冷启动
```

每层只记"可能不必做的工作"，不要在这一步取舍。
