# 工作账本

发现优化点的第一步不是测时间，而是回答：**这个操作做了哪些工作，每项多少次，每次多贵。**

---

## 术语

| 词 | 一句话 |
|---|---|
| self time | 函数自身耗时，不含子函数 |
| N+1 | 列表查 1 次，再对每行各查 1 次 |
| 头阻塞 | 一个慢请求占住连接/线程，后面的只能排队 |
| 伪共享 | 多线程改同一缓存行的不同变量，硬件仍要同步 |
| 读/写放大 | 想读 1 行却读整页，想写 1 条却写多份 |
| NUMA | 多内存节点，跨节点访问更慢 |
| cgroup | 资源限额组，限制 CPU/内存/IO |

---

## 一、什么算一项工作

必须能用一个动词描述、能数出次数：

- 计算：解析、编码、压缩、哈希、排序、正则
- 数据：查询、扫描、序列化、反序列化、拷贝、拼接
- 通信：建连、RPC、DNS、TLS、重试
- 同步：加锁、等待、轮询、上下文切换
- 存储：读页、写页、fsync、随机/顺序 IO
- 内存：分配、回收、缺页、GC

不要写"处理请求"这种不可数的工作项。

---

## 二、怎么枚举

| 来源 | 能拿到 | 注意 |
|---|---|---|
| 代码路径 | 调用顺序、循环、分支、同步点 | 先读热路径 |
| 日志 | 阶段耗时、次数、重试、错误 | 日志本身可能在热路径 |
| 指标/计数器 | 调用次数、字节、命中率、队列长度 | 证明"发生"，不证明"值得优化" |
| trace | 跨进程/跨网络的真实路径与等待 | 确认采样率与埋点开销 |
| 系统调用 | IO、锁、调度、缺页 | 只取与操作窗口对齐的部分 |
| 配置 | 池大小、超时、批量大小、缓存上限 | 默认值常是"开发友好" |

先画第一层路径图（按自然边界，不预设段数），优先拆平均耗时最高的几段，再逐段填工作项。

---

## 三、次数与频次

至少记两个数：每次操作发生多少次（含循环、批量、重试）、每秒/每天发生多少次操作。

```text
总成本/周期 = 单次操作内次数 × 周期内操作数 × 单次成本
```

常见漏算：重试/补偿/后台任务/日志监控；定时任务/消息消费/预热/健康检查；按用户/租户/分片的放大；失败路径。

---

## 四、单次成本：先记数量级

| 操作 | 量级 |
|---|---:|
| L1 缓存访问 | ~1 ns |
| 主存访问 | ~60–100 ns |
| 无竞争加解锁 | ~20 ns |
| 系统调用 | ~0.5–2 µs |
| 上下文切换 | ~2–5 µs |
| 1 KB JSON 序列化 | ~1–5 µs |
| 1 MB 内存拷贝 | ~50–100 µs |
| 1 MB 页缓存读 | ~100–300 µs |
| SSD 随机 4 KB 读 | ~50–150 µs |
| SSD 1 MB 顺序读 | ~1–3 ms |
| 同机房网络 RTT | ~0.3–1 ms |
| 机械盘寻道 | ~5–10 ms |
| 1 MB gzip | ~5–20 ms |
| 1 MB JSON 解析 | ~5–15 ms |

先判断理论成本与实际耗时是否同量级；差 10 倍以上就值得查。跨进程/跨网络/落盘优先于纯 CPU；单次成本低的项只有频次极高才值得优化。

---

## 五、账本字段

| 字段 | 说明 |
|---|---|
| 工作项 | 动词 + 对象 |
| 次数/操作 | 单次操作内发生多少次 |
| 频次 | 每秒/每天/每次构建多少次 |
| 单次成本 | 先数量级，有实测填实测 |
| 资源 | CPU/内存/磁盘/网络/锁 |
| 必要性 | 必须/可延后/可合并/可缓存/可消除 |
| 可消除比例 | 保守估计 30%/70%/100% |
| 证据 | 代码位置/计数/trace/实测 |

## 六、两个例子（数字示意）

**列表接口**

| 工作项 | 次数/请求 | 频次/秒 | 单次成本 | 资源 | 必要性 |
|---|---:|---:|---:|---|---|
| 鉴权 | 1 | 2k | 50 µs | CPU | 必须 |
| 查用户 | 1 | 2k | 0.5 ms | DB | 必须 |
| 查列表主表 | 1 | 2k | 1 ms | DB | 必须 |
| 逐条查详情 | 50 | 100k | 0.4 ms | DB | 可合并 |
| 序列化响应 | 1 | 2k | 300 µs | CPU | 可减 |
| 同步写日志 | 1 | 2k | 200 µs | 磁盘 | 可异步 |

最大项：逐条查详情 100k × 0.4 ms = 40 秒/秒 DB 时间；其次同步日志 0.4 秒/秒。

**批处理**

| 工作项 | 次数/任务 | 频次/天 | 单次成本 | 资源 | 必要性 |
|---|---:|---:|---:|---|---|
| 读输入 | 1 | 24 | 2 s | 磁盘 | 必须 |
| 逐行解析 | 10M | 24 | 2 µs | CPU | 可批量 |
| 逐行写库 | 10M | 24 | 1 ms | DB | 可批量 |
| 每 1000 行提交 | 10k | 24 | 5 ms | DB | 必须 |

最大项：逐行写库 10M × 1 ms ≈ 2.8 小时/任务。

## 七、账本常见错误

- 组件耗时当端到端：组件 100 ms，端到端 1 s，收益有限。
- 父子相加：并列阶段相加会超过总时长。
- 漏掉等待：只记 CPU/IO，不记锁、排队、重试。
- 漏掉频次：只算单次成本，没算每秒多少次。
- 计数器当收益：跳过的调用很多，但每次只值 0.1 µs。
- 问题在尾部时只算平均：重试、GC、锁饥饿会被平均掩盖。
